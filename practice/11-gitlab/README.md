# 11: GitLab

I use this module to practise the same workflow as the rest of this repository on GitLab instead of GitHub: merge requests instead of pull requests, a `.gitlab-ci.yml` pipeline instead of an Actions workflow and `glab` instead of `gh`.

| Part | What it covers |
| --- | --- |
| [11.1: Exercise](11.1-exercise) | A GitLab project, a protected branch, a merge request from the terminal and a first pipeline |
| [11.2: Extra Practice](11.2-extra-practice) | Merge methods, draft merge requests, suggested changes, pipeline rules and CI variables |
| [11.3: Self-Test](11.3-self-test) | Questions with no answers shown, to check what actually stuck |

## Why this matters to me

Plenty of teams, university groups and companies run on GitLab rather than GitHub. The ideas carry straight over, but the names, the menus and the CI file do not. Doing the full loop once here means the first real GitLab project I join feels familiar instead of new. My [git-unlocked](https://github.com/zaccesss/git-unlocked/tree/main/04-gitlab) guide has the full reference behind each step.
