# 14: Planning with GitHub Projects

I use this module to practise planning work across issues and pull requests with a GitHub project board, instead of keeping the plan in my head or a separate app.

| Part | What it covers |
| --- | --- |
| [14.1: Exercise](14.1-exercise) | A project for this repository, a board view, custom fields and the built-in workflows |
| [14.2: Extra Practice](14.2-extra-practice) | Sub-issues, milestones, a roadmap view, iterations and managing a project from the terminal |
| [14.3: Self-Test](14.3-self-test) | Questions with no answers shown, to check what actually stuck |

## Why this matters to me

Issues say what needs doing, a project says what comes next and what is stuck. Team projects and university group work both need that view. GitHub Projects keeps it next to the code rather than in a separate tool nobody updates.
