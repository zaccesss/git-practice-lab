# 07.2: Extra Practice

1. Open a pull request as a draft (`gh pr create --draft` or the draft option on GitHub), push a few more commits to it, then mark it ready for review (`gh pr ready`) once it is actually finished.
2. Use a GitHub Project (v2) board: add the issue from [07.1](../07.1-exercise) to a project, move it across status columns as I work on it.
3. Reference one issue from another without closing it, using plain `#<number>` in a comment rather than a closing keyword. Confirm GitHub still links them without closing either.
4. Convert a comment thread on an issue into its own issue, using GitHub's "Create issue from comment" if it is a discussion-worthy tangent.
5. Look at the repository's Insights > Community Standards page and confirm every file it checks for (README, CODE_OF_CONDUCT, SECURITY, CONTRIBUTING, issue templates) shows as present.
6. Try GitHub's private vulnerability reporting flow, on a throwaway repository, comparing it against the SECURITY.md-based process this repository already uses.
